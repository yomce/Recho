# 타임라인 싱크 및 데이터 구조 설계

## 핵심 원리

과거에 편집했던 비디오 레이어들의 싱크를 맞추고 복원하기 위한 핵심 원리는 각 비디오 클립(레이어)의 시간과 위치 정보를 최소한의 필수 데이터로 저장하는 것이다. 이 데이터를 기반으로 언제든지 편집 상태를 100% 재현할 수 있다.

## 저장 데이터 구조

각 비디오 클립을 DB에 저장할 때 필요한 최소한의 필수 데이터 필드는 다음과 같다. 이 데이터 구조는 `TrimmerState` 인터페이스와 일치한다.

- `sourceVideoId`: 어떤 원본 비디오 파일을 참조하는지에 대한 식별자.
- `startTime`: 원본 비디오에서 클립을 잘라내기 시작하는 시간 (단위: 초).
- `endTime`: 원본 비디오에서 클립을 잘라내기를 끝내는 시간 (단위: 초).
- `timelinePosition`: 전체 타임라인에서 해당 클립이 시작되는 위치 (단위: 초).

부가적으로 볼륨, 이퀄라이저 등 다른 편집 정보도 이 객체에 함께 저장될 수 있다.

## 복원 과정

1.  **데이터 로드:** 사용자가 과거 작업을 불러올 때, 서버 DB에서 해당 작업에 연결된 모든 클립들의 데이터 세트(startTime, endTime, timelinePosition 등)를 배열 형태로 가져온다.
2.  **상태 재구성:** 프론트엔드에서는 이 데이터 배열을 기반으로 `TrimmerState` 객체의 배열을 다시 생성한다.
3.  **렌더링:** `Timeline.tsx` 컴포넌트는 이 `TrimmerState` 배열을 props로 전달받는다.
    - 각 클립은 `timelinePosition` 값에 따라 타임라인의 정확한 위치에 렌더링된다.
    - 클립의 시각적인 길이는 `(endTime - startTime) * PIXELS_PER_SECOND` 공식을 통해 계산되어 렌더링된다.
    - 이를 통해 모든 클립의 위치와 길이가 정확하게 복원된다.

## 예외 처리: 포지션 정규화 (Normalization)

향후 기능 확장 시, 클립의 `timelinePosition`이 음수 값을 갖게 되는 경우가 발생할 수 있다. (예: 사용자가 클립을 타임라인의 시작점보다 더 왼쪽으로 드래그하는 경우)

이러한 상황을 처리하기 위해 '정규화' 과정을 도입할 수 있다.

1.  **최소값 탐색:** 타임라인에 배치된 모든 클립들의 `timelinePosition` 값 중에서 가장 작은 값을 찾는다. (예: -3.0)
2.  **정규화 적용:** 만약 가장 작은 값이 음수일 경우, 모든 클립의 `timelinePosition`에 해당 값의 절댓값을 더해준다.
    - `newPosition = oldPosition + abs(minValue)`
    - 예시: `newPosition = oldPosition + 3.0`
3.  **결과:** 모든 클립이 오른쪽으로 함께 이동하여, 가장 왼쪽에 있던 클립의 `timelinePosition`이 0이 된다. 이를 통해 타임라인의 상대적인 위치는 완벽하게 유지하면서, 음수 포지션으로 인한 문제를 방지할 수 있다. 이 과정은 시스템의 안정성과 데이터 무결성을 보장하는 중요한 예외 처리 방식이다.
